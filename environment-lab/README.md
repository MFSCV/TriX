# TriX application 0.5.0

TriX helps plan where AI models, tools and data-processing tasks run: describe hardware, runtimes and constraints, check compatibility, compare alternatives and export a portable environment configuration. With a configured model and enrolled external tools, her experimental orchestrator can delegate scoped implementation, testing, audit and delivery work.

The application is part of a broader proposed portable language and execution-contract programme. It is not the complete language/compiler or a generally qualified autonomous runtime. TriX uses she/her pronouns. Interface and technical documentation are in English.

Local mode uses explicit rules; it must not pretend to understand arbitrary requests. **“Generate a React application”** requires integrations; **“Generate a technical configuration”** produces a local planning artifact.

## Develop and verify

This application has no third-party runtime dependencies. The recorded checks use Node 24; no broader runtime-version qualification is implied.

```sh
npm run check
npm run benchmark
npm run dev
```

`public/` contains browser source; `runtime/` contains policy/model/MCP code; `worker/` contains authenticated APIs. `dist/` is generated by `npm run build`. The development server uses a disposable preview identity and in-memory storage, with no model/MCP credentials. It must not be deployed as the production identity adapter.

Build uses private `.openai/hosting.json` when present, or the generic `.openai/hosting.example.json` in the public source. Register a separate Site and configure real platform identity/storage before hosting your own copy. Keep keys in runtime secrets, outside source and browser code.

## CPU reference

Ask **“Run the pure CPU example”** to observe `(6 × 7) + 8 = 50`, or export a reference plan from its contextual editor and run:

```sh
node scripts/run-reference-plan.mjs TriX_Reference_CPU_Plan.json
node scripts/run-reference-plan.mjs TriX_Reference_CPU_Plan.json --state cpu-state.json
```

The optional state argument explicitly authorizes the named checkpoint and sibling lock/temporary files. The CLI refuses mismatched/corrupted completed state. Its six registered pure operations cannot access arbitrary files, processes, networks, providers or plugins; only the wrapper performs the named I/O. It is not the general agent CLI proposed in the conversion programme.

## Read evidence correctly

A response is not an implementation. A planning pass is not physical hardware qualification. A hash identifies content but does not authenticate its producer. A model review is not independent audit approval. A deployment receipt is separate from verified application behaviour.

Benchmarks report sample size, environment and scope. No live model latency, TTFT, real MCP/target output, production SLO, independent security certification or complete accessibility conformance is claimed. See the open gaps and current evidence before enabling live operations.

Existing owner-private hosting remains private. The public source export excludes its Site identity, credentials, user records, generated deployment bundles and browser screenshots. Public source does not change the running application’s audience.
