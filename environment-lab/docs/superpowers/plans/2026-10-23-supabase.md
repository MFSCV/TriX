# Supabase Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect TriX to durable, isolated Supabase storage and bounded background execution.
**Architecture:** Server-only authenticated Edge bridge, transactional Postgres RPC, private Storage and pgmq. Preserve the Worker API and R2 legacy tasks. Share the tested runtime with the bounded Edge consumer.
**Tech Stack:** Dependency-free JavaScript ESM, PostgreSQL 17, Supabase Edge/Deno, Storage, Vault, pgmq, pg_cron and pg_net.
**Spec:** docs/superpowers/specs/2026-10-23-supabase.md

## Global Constraints
- Preserve private audience and ChatGPT sign-in. Never expose service keys in browser/model/public exports.
- One bounded runtime step per delivery, 100-second runtime lease, exact-revision receipt gates.
- Unknown external effects never replay. Existing R2 tasks continue in R2 without dual writes.
- Three private buckets: context-files, artifacts, audit-reports. No Realtime or pgvector yet.
- General reasoning requires a real model credential and selected model.

## Review Focus
- Partial storage configuration must fail closed, never silently change persistence providers.
- Simultaneous browser/background requests must use one shared CAS/lease.
- Cron authentication and queue claim tokens must reject unauthenticated and stale workers.
- Object paths and owner subjects must not allow cross-account access.
- CPU infrastructure evidence must not be presented as model or external audit acceptance.
